# 구현 및 검증 기록

2026-11-09 · Unity 6000.4.8f1 · Windows

## 솔로

- SoloScene1/2 원본을 백업한 뒤 기존 지형·건물·군인 이동·철문 상호작용을 유지했습니다.
- SoloScene3/4를 추가하고 네 씬의 진행을 연결했습니다. 저장된 분기와 문서를 씬 전환 및 재시작에 유지합니다.
- 규칙 검사 17개 통과. 슬라이딩 퍼즐 200개 시드에서 풀 수 있는 배열이며 시작부터 완성되어 있지 않음을 확인했습니다.
- 상층 분기 통합 검사 13개: 실제 UI 버튼으로 시작 대사, 프로필, 오답/정답 출입 인증, 승강기, 구조 성공, 서약 퍼즐, 숫자 퍼즐, 무전, 최종 씬 진입.
- 추락 분기 통합 검사 8개: X 타이밍을 실제로 놓치고 분기, 부상자 조사, 벽 밀기, 성조기 조각을 합법적인 버튼 순서로 이동하여 해결, 기존 연구실 문 열림, 무전 합류.
- 최종 구간 검사 10개: 64m 복도에서 CharacterController 이동·점프로 장애물 통과, 방화문 잠금, 비상구 붕괴, 낮은 환풍구의 직선과 모서리 통과, 건물 침하와 엔딩, 사망·환풍구 체크포인트 복구.
- B2의 감옥 출구 x=106→99 및 연구 구역 x=99→64를 실제 충돌 처리와 이동으로 확인했습니다.
- UI 버튼/진행 검사는 자동 입력이며, 전체 구간을 사람이 연속 조작한 플레이테스트는 아닙니다. 추격 동선 충돌 검사에서는 추격자를 잠시 정지시켜 이동 가능성을 분리 검증했습니다.
- 솔로 시작 화면에서 멀티게임 진입 버튼과 전환 코드를 제거했습니다. 솔로와 멀티는 별도의 빌드 프로필과 실행 파일로 구동합니다.
- 한국어 퍼즐·자막·메뉴를 1280×720 Game View로 시각 확인했습니다.
- 실제 프레임 카운터가 진행되는 상태에서 검사했습니다. 테스트 전 체크포인트를 보관하고 종료 후 복원했습니다.

## 마이크 끊김 수정

기존 구현은 작은 PCM 큐를 스트리밍 AudioClip의 읽기 콜백에서 소모했습니다. 디코더가 요청하는 묶음이 큐보다 크면 주기적으로 큐가 비거나 넘칠 수 있었습니다. 수신 패킷이 순서대로 오지 않으면 아직 재생할 기회가 있는 패킷까지 폐기했습니다.

변경 내용:

- 클립 없는 `OnAudioFilterRead` 생성기로 출력 장치의 DSP 주기에 맞춰 음성을 재생합니다. Unity 문서상 이 콜백은 오디오 스레드에서 실행되므로 해당 경로에서는 사전 할당한 관리 배열만 사용하고 Unity API를 호출하지 않습니다. [Unity 공식 문서](https://docs.unity3d.com/cn/6000.0/ScriptReference/MonoBehaviour.OnAudioFilterRead.html)
- 16kHz PCM을 실제 출력 샘플레이트/채널 수로 변환합니다. 일반 설정의 시작 여유는 80ms이며 큰 DSP 블록에는 필요한 만큼 늘어납니다.
- 32개 패킷 슬롯으로 재생 전 순서 뒤바뀜을 복원합니다. 누락 패킷은 직전 프레임을 점차 줄여 보완하고, 장시간 공백·재접속·라운드 변경 때 오래된 음성을 비웁니다.
- 마이크 저주파/DC 제거, 입력 게인(0.5~3), 상대 음성 볼륨(0~1)을 추가했습니다. 작은 목소리를 잘라내는 강제 노이즈 게이트는 사용하지 않습니다.
- A가 B만 듣는 기존 규칙, 두 퍼즐 해결 후 양방향 전환, 음소거, 장치 선택을 유지했습니다.

검증:

- 기존 음성 버퍼·역할 검사 30개 통과. 손실 프레임의 기대값을 새 보완 방식에 맞췄습니다.
- 추가 검사 41개 통과. 그중 24개는 16/44.1/48kHz × DSP 256/512/1024/2048 × 정상/지연·재정렬·손실 조건입니다. 각 10초 시뮬레이션의 준비 구간 이후 무음 콜백 및 버퍼 언더런 0회였습니다. 실제 인터넷의 모든 장애를 보장하는 결과는 아닙니다.
- Unity 오디오 스레드에서 합성 신호를 재생하고 최종 AudioListener 출력까지 확인했습니다. 장치 DSP 검사에서 언더런 0회였습니다.
- Editor 호스트 + 별도 Windows Development Player의 실제 루프백 네트워크에서 35개 검사 통과. B→A 실제 출력, 완료 후 A→B, 이전 라운드 패킷 거부, 음소거, 재시작 권한 복구, 연결 해제·재접속을 확인했습니다. 출력 피크 0.1220703.
- 설치된 마이크를 열 수 있음을 검사했으며 마이크 녹음 파일은 저장하지 않았습니다. 별도 두 PC의 Wi-Fi와 사용자의 헤드셋 조합으로 육성 통화를 청취하는 검사는 하지 않았습니다.
- 기존 멀티게임 규칙·GPU 흑백 43개, 캠페인 38개 회귀 검사 통과.

오디오 필터 적용 전 AudioSource 데이터를 검사하면 무음으로 보일 수 있으므로, Development Probe는 필터 이후 피크를 보고합니다. 최종 출력 도달 여부는 별도의 AudioListener 검사로도 확인했습니다.

## 빌드 및 자산 범위

솔로 Windows 빌드는 `Builds/HollowCreek/HollowCreek.exe`이며 SoloScene1~4만 포함합니다. 멀티 Windows 빌드는 `Builds/MultiEscape/MultiEscape.exe`이며 MultiScene1만 포함합니다. 두 게임 사이에 씬 전환은 없습니다. 각 실행 파일이 들어 있는 폴더 전체를 복사하세요. 두 PC의 멀티 테스트에는 같은 최신 MultiEscape 폴더를 사용하세요.

`Assets/BuildProfiles/SoloWindows.asset`과 `MultiplayerWindows.asset`은 각각 독립적인 씬 목록을 사용합니다. 전역 대체 목록에도 솔로 씬만 남겼습니다. 씬 의존성 검사에서 상대 모드의 게임 스크립트 참조가 없음을 확인했습니다 (`independent-scenes.txt`). 에디터의 Game Builds 메뉴로 씬 그룹 선택 및 모드별 빌드가 가능합니다.

제공된 성조기 이미지 파일이 없어 퍼즐 이미지를 직접 제작했습니다. 18개 대사는 임시 한국어 합성 음성입니다. N의 절차형 모델, 동료 사망 동작, 시설 침하는 기능 검증용 연출이며 최종 캐릭터 아트·성우 녹음·애니메이션 제작을 의미하지 않습니다.

독립 프로필로 다시 만든 두 Release 빌드 모두 성공했습니다. 각각 오류 0개, 경고 486개이며, 경고는 기존 Unity Inference 셰이더와 Pipeline Player 자동화 설정 안내입니다. 솔로 결과에는 씬 파일 4개, 멀티 결과에는 씬 파일 1개만 포함됩니다. 최종 빌드 요약은 `independent-build-report.json`에 보관합니다.

독립 실행 확인: SoloWindows Play Mode에서 시작 화면의 멀티 버튼 및 멀티 세션 부재, SoloScene1~4 로드 가능, MultiScene1 로드 불가를 확인했습니다. MultiplayerWindows Play Mode에서는 멀티 로비와 입력/수신 음량 슬라이더, 솔로 캠페인 부재, MultiScene1 로드 가능, SoloScene1~4 로드 불가를 확인했습니다. 검사 진입점은 `TestHollowCreek.SoloIsolation`과 `MultiplayerIsolation`입니다.
